# ESP32 智能家居控制系统错误规范

## 1. 概述

本规范定义了ESP32智能家居控制系统的错误分类、错误代码格式、错误记录格式以及错误处理流程，旨在提高系统的可维护性和故障排查效率。

## 2. 错误分类

### 2.1 系统级错误
- **硬件错误**：与硬件相关的错误，如传感器故障、GPIO引脚异常等
- **软件错误**：软件逻辑错误、内存管理错误等
- **通信错误**：WiFi连接错误、MQTT通信错误等
- **配置错误**：配置文件错误、参数设置错误等

### 2.2 模块级错误
- **WiFi模块错误**：连接失败、断开连接等
- **GPIO模块错误**：引脚配置错误、读写错误等
- **传感器模块错误**：数据采集失败、校准错误等
- **设备控制模块错误**：设备控制失败、状态更新错误等
- **Web模块错误**：服务器启动失败、请求处理错误等

## 3. 错误代码格式

错误代码采用8位十六进制格式，结构如下：

```
XXYYZZ
```

- **XX**：错误类型（01-硬件，02-软件，03-通信，04-配置）
- **YY**：错误模块（01-WiFi，02-GPIO，03-传感器，04-设备控制，05-Web）
- **ZZ**：具体错误编号（00-FF）

### 3.1 示例错误代码

| 错误代码 | 错误类型 | 错误模块 | 具体错误 |
|---------|---------|---------|--------|
| 010201  | 硬件错误 | GPIO模块 | 引脚初始化失败 |
| 020301  | 软件错误 | 传感器模块 | 数据解析错误 |
| 030101  | 通信错误 | WiFi模块 | 连接超时 |
| 040501  | 配置错误 | Web模块 | 服务器配置错误 |

## 4. 错误记录格式

每个错误记录应包含以下信息：

| 字段名 | 类型 | 描述 | 示例 |
|-------|------|------|------|
| timestamp | 字符串 | 错误发生时间戳（本地时间格式） | 2025-12-10 15:43:30 |

**注意**：时间戳应通过运行命令`date +"%Y-%m-%d %H:%M:%S"`获取实际时间，确保时间准确性。
| error_code | 字符串 | 错误代码 | 030101 |
| error_level | 字符串 | 错误级别（INFO, WARN, ERROR, FATAL） | ERROR |
| module | 字符串 | 错误发生模块 | WiFiManager |
| function | 字符串 | 错误发生函数 | connect() |
| description | 字符串 | 错误描述 | WiFi连接超时 |
| additional_info | 字符串 | 额外信息（可选） | SSID: my_wifi |

### 4.1 示例错误记录

```json
{
  "timestamp": "2024-01-01T12:00:00Z",
  "error_code": "030101",
  "error_level": "ERROR",
  "module": "WiFiManager",
  "function": "connect()",
  "description": "WiFi连接超时",
  "additional_info": "SSID: my_wifi, Timeout: 30s"
}
```

## 5. 错误处理流程

### 5.1 错误检测
- 在关键函数中添加错误检测代码
- 对外部依赖调用（如传感器读数、WiFi连接）进行错误检查

### 5.2 错误报告
- 发生错误时，记录详细的错误信息到日志文件
- 严重错误（ERROR和FATAL级别）应通过串口输出
- 可选：将严重错误发送到远程服务器

### 5.3 错误恢复
- 对于非致命错误，尝试自动恢复（如重新连接WiFi）
- 对于致命错误，记录错误信息并重启系统

## 6. 错误日志管理

### 6.1 日志存储位置
- 临时日志：RAM缓冲区（重启后丢失）
- 持久化日志：SPIFFS文件系统

### 6.2 日志旋转
- 当日志文件达到最大大小（默认1MB）时，自动旋转
- 保留最近3个日志文件

### 6.3 日志检索
- 提供日志检索功能，支持按时间范围、错误级别、错误代码等条件查询

## 8. 错误处理最佳实践

1. **明确的错误返回值**：函数应返回明确的错误代码或状态
2. **详细的错误信息**：记录足够的上下文信息，便于排查问题
3. **错误传播**：在调用链中适当传播错误，避免静默失败
4. **资源清理**：发生错误时，确保正确清理已分配的资源
5. **用户友好的错误提示**：对于用户可见的错误，提供清晰易懂的提示
6. **定期审查错误日志**：定期分析错误日志，识别系统问题和改进点
