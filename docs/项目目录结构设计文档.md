## 2. 目录功能详细说明

### 2.1 src/ - 源代码目录

#### 2.1.1 src/core/ - 核心功能模块
- **RuleEngine**：规则引擎，实现基于条件的设备联动控制
- **AlarmManager**：告警管理器，处理烟雾传感器的告警逻辑
- **DataProcessor**：数据处理器，负责数据的滤波和处理
- **Rule**：规则类，定义规则的结构和行为

#### 2.1.2 src/devices/ - 设备模块
- **Device**：设备抽象类，定义设备的通用接口
- **DeviceManager**：设备管理器，负责所有设备的统一管理
- **SmartLight**：智能灯类，实现智能灯的控制功能
- **SmartSwitch**：智能开关类，实现智能开关的控制功能

#### 2.1.3 src/sensors/ - 传感器模块
- **EnvironmentSensor**：环境传感器抽象类，定义环境传感器的通用接口
- **EnvironmentManager**：环境管理器，负责环境传感器数据的采集与管理
- **TemperatureSensor**：温度传感器类，实现温度数据的采集
- **HumiditySensor**：湿度传感器类，实现湿度数据的采集
- **LightSensor**：光照传感器类，实现光照强度数据的采集
- **SmokeSensor**：烟雾传感器类，实现烟雾浓度数据的采集

#### 2.1.4 src/utils/ - 工具模块
- **WiFiManager**：WiFi管理器，负责网络连接管理
- **GPIOController**：GPIO控制器，负责硬件引脚的控制
- **DataProcessor**：数据处理器，负责数据的滤波和处理
- **EEPROMStorage**：EEPROM存储，负责关键数据的持久化存储
- **SPIFFSStorage**：SPIFFS存储，负责文件系统的管理
- **DataLogger**：数据日志器，负责系统日志的记录

#### 2.1.5 src/web/ - Web界面模块
- **WebServer**：Web服务器，处理HTTP请求和响应
- **webpage.h**：主页面HTML内容
- **styles.h**：CSS样式定义
- **scripts.h**：JavaScript交互逻辑

#### 2.1.6 src/main.cpp - 主程序入口
- 系统初始化
- 各模块的实例化和配置
- 主循环函数

### 2.2 include/ - 公共头文件目录

#### 2.2.1 include/definitions.h - 全局定义和常量
- 设备类型定义
- 传感器类型定义
- 告警级别定义
- 日志级别定义

#### 2.2.2 include/types.h - 自定义类型定义

- 环境数据结构体
- 规则结构体
- 告警设置结构体

#### 2.2.3 include/config.h - 配置参数
- WiFi配置参数（SSID、密码等）
- 传感器配置参数（采样频率等）
- 存储配置参数（日志大小等）
- 告警配置参数（阈值等）

### 2.3 data/ - SPIFFS文件系统数据目录

## 3. 文件组织原则

### 3.1 头文件和源文件分离
- 每个类的声明放在头文件（.h）中
- 每个类的实现放在源文件（.cpp）中
- 头文件使用预处理指令防止重复包含

### 3.2 模块内聚原则
- 功能相关的类和函数放在同一个目录下
- 每个模块只负责一个特定的功能域

### 3.3 依赖关系管理
- 低层次模块依赖高层次模块通过接口（抽象类）
- 避免循环依赖
- 使用前向声明减少头文件依赖

### 3.4 命名规范
- 目录名：小写字母，单词间用下划线分隔
- 文件名：首字母大写的驼峰命名法（如SmartLight.h）
- 类名：首字母大写的驼峰命名法
- 函数名：首字母小写的驼峰命名法
- 变量名：首字母小写的驼峰命名法
- 常量名：全大写，单词间用下划线分隔

## 5. 代码组织规范

### 5.1 头文件规范

```cpp
#ifndef DEVICE_H
#define DEVICE_H

#include <Arduino.h>
#include "definitions.h"

class Device {
public:
    virtual bool getStatus() = 0;
    virtual bool setStatus(bool status) = 0;
    virtual String getType() = 0;
    virtual String getId() = 0;
    virtual int getPin() = 0;
};

#endif // DEVICE_H
```

### 5.2 源文件规范

```cpp
#include "Device.h"

// Device抽象类的通用实现（如果有）

// 其他设备类的实现可以放在各自的源文件中
```

### 5.3 主程序规范

```cpp
#include <Arduino.h>
#include "config.h"
#include "WiFiManager.h"
#include "DeviceManager.h"
#include "EnvironmentManager.h"
#include "RuleEngine.h"
#include "AlarmManager.h"
#include "WebServer.h"
#include "DataLogger.h"

// 全局对象声明
WiFiManager wifiManager(SSID, PASSWORD);
SPIFFSStorage spiffsStorage;
DataLogger logger(&spiffsStorage, "/logs.txt", MAX_LOG_SIZE);
DeviceManager deviceManager;
EnvironmentManager envManager;
RuleEngine ruleEngine(&deviceManager, &envManager);
AlarmManager alarmManager(&logger, nullptr); // 告警设备将在setup中设置
WebServer webServer(&wifiManager, &deviceManager, &envManager, &alarmManager, &ruleEngine);

void setup() {
    // 初始化串口
    Serial.begin(115200);
    
    // 初始化存储
    spiffsStorage.init();
    
    // 初始化日志
    logger.log("INFO", "系统启动");
    
    // 初始化WiFi
    wifiManager.connect();
    logger.log("INFO", "WiFi连接成功，IP地址：" + wifiManager.getIPAddress().toString());
    
    // 初始化设备
    deviceManager.loadDeviceStates();
    logger.log("INFO", "设备初始化完成");
    
    // 初始化传感器
    envManager.init();
    logger.log("INFO", "传感器初始化完成");
    
    // 初始化规则引擎
    ruleEngine.loadRulesFromStorage();
    logger.log("INFO", "规则引擎初始化完成");
    
    // 初始化告警管理器
    Device* alarmDevice = deviceManager.getDevice("buzzer");
    alarmManager.setAlarmDevice(alarmDevice);
    logger.log("INFO", "告警管理器初始化完成");
    
    // 初始化Web服务器
    webServer.init();
    logger.log("INFO", "Web服务器初始化完成，访问地址：http://" + wifiManager.getIPAddress().toString());
}

void loop() {
    // 检查WiFi连接
    wifiManager.checkConnection();
    
    // 处理Web服务器请求
    webServer.handleClient();
    
    // 读取传感器数据
    envManager.readAllSensors();
    
    // 评估规则
    ruleEngine.evaluateRules();
    
    // 检查告警
    float smokeValue = envManager.getDataByType("smoke");
    alarmManager.checkAlarm(smokeValue);
    
    // 延迟
    delay(1000);
}
```

## 6. 项目构建和上传流程

### 6.1 PlatformIO构建流程

1. **安装依赖**：`platformio lib install`
2. **构建项目**：`platformio run`
3. **上传固件**：`platformio run --target upload`
4. **上传SPIFFS文件**：`platformio run --target uploadfs`
5. **监控串口**：`platformio device monitor`

### 6.2 Arduino IDE构建流程

1. **安装依赖库**：通过Arduino库管理器安装所需库
2. **配置板型**：选择ESP32开发板
3. **配置端口**：选择正确的串口
4. **构建项目**：点击"验证"按钮
5. **上传固件**：点击"上传"按钮
6. **上传SPIFFS文件**：使用ESP32 Sketch Data Upload工具上传数据目录

## 7. 扩展和维护建议

### 7.1 代码扩展

- 新增设备：在`src/devices/`目录下创建新的设备类，继承自Device抽象类
- 新增传感器：在`src/sensors/`目录下创建新的传感器类，继承自EnvironmentSensor抽象类
- 新增功能模块：在`src/core/`目录下创建新的功能模块类

### 7.2 代码维护

- 定期更新第三方库到最新版本
- 保持代码注释的完整性和准确性
- 遵循统一的命名规范和代码风格
- 及时修复已知的bug和问题
- 定期进行代码审查和优化

### 7.3 文档维护

- 代码修改后及时更新相关文档
- 保持文档的一致性和准确性
- 新增功能时同步更新设计文档和API文档

## 8. 总结

本项目目录结构设计遵循了模块化、分层架构的原则，将系统划分为多个功能独立的模块，每个模块内部高内聚，模块间低耦合。这种结构设计有助于：

1. **提高代码可维护性**：模块职责清晰，便于定位和修复问题
2. **提高代码可复用性**：各模块可以独立复用和测试
3. **便于团队协作**：不同开发人员可以同时开发不同模块
4. **支持系统扩展**：新增功能或设备时只需添加相应模块
5. **提高代码质量**：模块化设计便于进行单元测试和集成测试

通过这种清晰的目录结构设计，项目可以更好地适应未来的功能扩展和维护需求。
